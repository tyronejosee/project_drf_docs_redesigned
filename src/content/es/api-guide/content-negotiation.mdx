# Negociación de contenido

> HTTP dispone de varios mecanismos para la "negociación de contenido": el proceso de seleccionar la mejor representación para una respuesta cuando hay múltiples representaciones disponibles.
>
> &mdash; [RFC 2616][cite], Fielding et al.

[cite]: https://www.w3.org/Protocols/rfc2616/rfc2616-sec12.html

La negociación de contenido es el proceso de seleccionar una de las varias representaciones posibles para devolver a un cliente, en función de las preferencias del cliente o del servidor.

## Determinación del renderizador aceptado

Django REST framework utiliza un estilo sencillo de negociación de contenido para determinar qué tipo de medio (media type) debe devolverse a un cliente, basándose en los renderizadores disponibles, las prioridades de cada uno de esos renderizadores y la cabecera `Accept:` del cliente. El estilo utilizado es en parte impulsado por el cliente y en parte por el servidor.

1. Se da preferencia a los tipos de medio más específicos frente a los menos específicos.
2. Si varios tipos de medio tienen la misma especificidad, se da preferencia según el orden de los renderizadores configurados para la vista.

Por ejemplo, dada la siguiente cabecera `Accept`:

```http
application/json; indent=4, application/json, application/yaml, text/html, */*
```

Las prioridades para cada uno de los tipos de medio serían:

- `application/json; indent=4`
- `application/json`, `application/yaml` y `text/html`
- `*/*`

Si la vista solicitada solo estuviera configurada con renderizadores para `YAML` y `HTML`, entonces REST framework seleccionaría el que aparezca primero en la lista `renderer_classes` o en la configuración `DEFAULT_RENDERER_CLASSES`.

Para más información sobre la cabecera `HTTP Accept`, consulte [RFC 2616][accept-header]

---

**Nota**: REST framework no tiene en cuenta los valores "q" al determinar la preferencia. El uso de valores "q" afecta negativamente al cacheo y, en opinión del autor, son un enfoque innecesario y demasiado complejo para la negociación de contenido.

Este es un enfoque válido ya que la especificación HTTP deja deliberadamente subespecificado cómo un servidor debe ponderar las preferencias basadas en servidor frente a las del cliente.

## Negociación de contenido personalizada

Es poco probable que desee proporcionar un esquema de negociación de contenido personalizado para REST framework, pero puede hacerlo si es necesario. Para implementar un esquema personalizado, sobrescriba `BaseContentNegotiation`.

Las clases de negociación de contenido de REST framework se encargan de la selección tanto del parser apropiado para la solicitud como del renderizador apropiado para la respuesta, así que debe implementar los métodos `.select_parser(request, parsers)` y `.select_renderer(request, renderers, format_suffix)`.

El método `select_parser()` debe devolver una de las instancias de parser de la lista de parsers disponibles, o `None` si ninguno puede manejar la solicitud entrante.

El método `select_renderer()` debe devolver una tupla de dos elementos (instancia de renderer, tipo de medio), o lanzar una excepción `NotAcceptable`.

### Ejemplo

La siguiente es una clase de negociación de contenido personalizada que ignora la solicitud del cliente al seleccionar el parser o el renderer apropiado.

```python
from rest_framework.negotiation import BaseContentNegotiation

class IgnoreClientContentNegotiation(BaseContentNegotiation):
    def select_parser(self, request, parsers):
        """
        Selecciona el primer parser en la lista `.parser_classes`.
        """
        return parsers[0]

    def select_renderer(self, request, renderers, format_suffix):
        """
        Selecciona el primer renderer en la lista `.renderer_classes`.
        """
        return (renderers[0], renderers[0].media_type)
```

## Configuración de la negociación de contenido

La clase de negociación de contenido por defecto puede establecerse globalmente mediante la configuración `DEFAULT_CONTENT_NEGOTIATION_CLASS`. Por ejemplo, la siguiente configuración usaría nuestra clase `IgnoreClientContentNegotiation` de ejemplo.

```python
REST_FRAMEWORK = {
    'DEFAULT_CONTENT_NEGOTIATION_CLASS': 'myapp.negotiation.IgnoreClientContentNegotiation',
}
```

También puede establecer la negociación de contenido para una vista individual o un viewset usando las vistas basadas en clases `APIView`.

```python
from myapp.negotiation import IgnoreClientContentNegotiation
from rest_framework.response import Response
from rest_framework.views import APIView

class NoNegotiationView(APIView):
    """
    Un ejemplo de vista que no realiza negociación de contenido.
    """
    content_negotiation_class = IgnoreClientContentNegotiation

    def get(self, request, format=None):
        return Response({
            'tipo de medio aceptado': request.accepted_renderer.media_type
        })
```
