# Filtrado

> El QuerySet raíz proporcionado por el Manager describe todos los objetos en la tabla de la base de datos. Generalmente, sin embargo, necesitarás seleccionar solo un subconjunto del conjunto completo de objetos.
>
> &mdash; [Django documentation][cite]

El comportamiento predeterminado de las vistas de lista genéricas de REST framework es devolver el queryset completo para un model manager. A menudo querrás que tu API restrinja los elementos devueltos por el queryset.

La forma más simple de filtrar el queryset de cualquier vista que hereda de `GenericAPIView` es sobreescribir el método `.get_queryset()`.

Sobrescribir este método te permite personalizar el queryset devuelto por la vista de varias maneras diferentes.

## Filtrado contra el usuario actual

Podrías querer filtrar el queryset para asegurar que solo se devuelvan resultados relevantes para el usuario actualmente autenticado que realiza la solicitud.

Puedes hacerlo filtrando basado en el valor de `request.user`.

Por ejemplo:

```python
from myapp.models import Purchase
from myapp.serializers import PurchaseSerializer
from rest_framework import generics

class PurchaseList(generics.ListAPIView):
    serializer_class = PurchaseSerializer

    def get_queryset(self):
        """
        This view should return a list of all the purchases
        for the currently authenticated user.
        """
        user = self.request.user
        return Purchase.objects.filter(purchaser=user)
```

## Filtrado contra la URL

Otro estilo de filtrado podría implicar restringir el queryset basado en alguna parte de la URL.

Por ejemplo, si tu configuración de URLs contuviera una entrada como esta:

```python
re_path('^purchases/(?P<username>.+)/$', PurchaseList.as_view()),
```

Podrías entonces escribir una vista que devuelva un queryset de compras filtrado por la porción de nombre de usuario de la URL:

```python
class PurchaseList(generics.ListAPIView):
    serializer_class = PurchaseSerializer

    def get_queryset(self):
        """
        Esta vista debería devolver una lista de todas las compras para
        el usuario según lo determinado por la porción de nombre de usuario de la URL.
        """
        username = self.kwargs['username']
        return Purchase.objects.filter(purchaser__username=username)
```

## Filtrado contra parámetros de consulta

Un ejemplo final de filtrado del queryset inicial sería determinar el queryset inicial basado en parámetros de consulta en la url.

Podemos sobreescribir `.get_queryset()` para manejar URLs como `http://example.com/api/purchases?username=denvercoder9`, y filtrar el queryset solo si el parámetro `username` está incluido en la URL:

```python
class PurchaseList(generics.ListAPIView):
    serializer_class = PurchaseSerializer

    def get_queryset(self):
        """
        Opcionalmente restringe las compras devueltas a un usuario dado,
        filtrando contra un parámetro de consulta `username` en la URL.
        """
        queryset = Purchase.objects.all()
        username = self.request.query_params.get('username')
        if username is not None:
            queryset = queryset.filter(purchaser__username=username)
        return queryset
```

# Filtrado Genérico

Además de poder sobreescribir el queryset predeterminado, REST framework también incluye soporte para backends de filtrado genéricos que te permiten construir fácilmente búsquedas y filtros complejos.

Los filtros genéricos también pueden presentarse como controles HTML en la API navegable y la API de administración.

![Ejemplo de Filtro](../img/filter-controls.png)

## Configuración de backends de filtro

Los backends de filtro predeterminados pueden establecerse globalmente, usando la configuración `DEFAULT_FILTER_BACKENDS`. Por ejemplo:

```python
REST_FRAMEWORK = {
    'DEFAULT_FILTER_BACKENDS': ['django_filters.rest_framework.DjangoFilterBackend']
}
```

También puedes establecer los backends de filtro por vista, o por viewset,
usando las vistas basadas en clases `GenericAPIView`.

```python
import django_filters.rest_framework
from django.contrib.auth.models import User
from myapp.serializers import UserSerializer
from rest_framework import generics

class UserListView(generics.ListAPIView):
    queryset = User.objects.all()
    serializer_class = UserSerializer
    filter_backends = [django_filters.rest_framework.DjangoFilterBackend]
```

## Filtrado y búsquedas de objetos

Nota que si un backend de filtro está configurado para una vista, además de ser usado para filtrar vistas de lista, también se usará para filtrar los querysets usados para devolver un solo objeto.

Por ejemplo, dado el ejemplo anterior, y un producto con un id de `4675`, la siguiente URL devolvería el objeto correspondiente, o una respuesta 404, dependiendo de si las condiciones de filtrado fueron cumplidas por la instancia del producto dada:

```http
http://example.com/api/products/4675/?category=clothing&max_price=10.00
```

## Sobreescribiendo el queryset inicial

Nota que puedes usar tanto un `.get_queryset()` sobrescrito como filtrado genérico juntos, y todo funcionará como se espera. Por ejemplo, si `Product` tuviera una relación muchos-a-muchos con `User`, llamada `purchase`, podrías querer escribir una vista como esta:

```python
class PurchasedProductsList(generics.ListAPIView):
    """
    Devuelve una lista de todos los productos que el usuario
    autenticado alguna vez compró, con filtrado opcional.
    """
    model = Product
    serializer_class = ProductSerializer
    filterset_class = ProductFilter

    def get_queryset(self):
        user = self.request.user
        return user.purchase_set.all()
```

# API Guide

## DjangoFilterBackend

La librería [`django-filter`][django-filter-docs] incluye una clase `DjangoFilterBackend` que
soporta filtrado de campo altamente personalizable para REST framework.

Para usar `DjangoFilterBackend`, primero instala `django-filter`.

```bash
pip install django-filter
```

Luego añade `'django_filters'` a las `INSTALLED_APPS` de Django:

```python
INSTALLED_APPS = [
    ...
    'django_filters',
    ...
]
```

Ahora deberías añadir el backend de filtro a tu configuración:

```python
REST_FRAMEWORK = {
    'DEFAULT_FILTER_BACKENDS': ['django_filters.rest_framework.DjangoFilterBackend']
}
```

O añadir el backend de filtro a una Vista o ViewSet individual.

```python
from django_filters.rest_framework import DjangoFilterBackend

class UserListView(generics.ListAPIView):
    ...
    filter_backends = [DjangoFilterBackend]
```

Si todo lo que necesitas es filtrado simple basado en igualdad, puedes establecer un atributo `filterset_fields` en la vista, o viewset, listando el conjunto de campos contra los que deseas filtrar.

```python
class ProductList(generics.ListAPIView):
    queryset = Product.objects.all()
    serializer_class = ProductSerializer
    filter_backends = [DjangoFilterBackend]
    filterset_fields = ['category', 'in_stock']
```

Esto creará automáticamente una clase `FilterSet` para los campos dados, y te permitirá hacer solicitudes como:

```http
http://example.com/api/products?category=clothing&in_stock=True
```

Para requisitos de filtrado más avanzados puedes especificar una clase `FilterSet` que debería ser usada por la vista.
Puedes leer más sobre `FilterSet`s en la [documentación de django-filter][django-filter-docs].
También se recomienda que leas la sección sobre [integración con DRF][django-filter-drf-docs].

## SearchFilter

La clase `SearchFilter` soporta búsqueda simple basada en un único parámetro de consulta, y se basa en la [funcionalidad de búsqueda del admin de Django][search-django-admin].

Cuando está en uso, la API navegable incluirá un control `SearchFilter`:

![Filtro de Búsqueda](../img/search-filter.png)

La clase `SearchFilter` solo se aplicará si la vista tiene establecido un atributo `search_fields`. El atributo `search_fields` debería ser una lista de nombres de campos de tipo texto en el modelo, como `CharField` o `TextField`.

```python
from rest_framework import filters

class UserListView(generics.ListAPIView):
    queryset = User.objects.all()
    serializer_class = UserSerializer
    filter_backends = [filters.SearchFilter]
    search_fields = ['username', 'email']
```

Esto permitirá al cliente filtrar los elementos en la lista haciendo consultas como:

```http
http://example.com/api/users?search=russell
```

También puedes realizar búsquedas relacionadas en un ForeignKey o ManyToManyField con la notación de doble guión bajo de la API de búsqueda:

```python
search_fields = ['username', 'email', 'profile__profession']
```

Para campos [JSONField][JSONField] y [HStoreField][HStoreField] puedes filtrar basado en valores anidados dentro de la estructura de datos usando la misma notación de doble guión bajo:

```python
search_fields = ['data__breed', 'data__owner__other_pets__0__name']
```

Por defecto, las búsquedas usarán coincidencias parciales insensibles a mayúsculas/minúsculas. El parámetro de búsqueda puede contener múltiples términos de búsqueda, los cuales deberían estar separados por espacios en blanco y/o comas. Si se usan múltiples términos de búsqueda, los objetos solo se devolverán en la lista si todos los términos proporcionados coinciden. Las búsquedas pueden contener _frases entre comillas_ con espacios, cada frase se considera como un único término de búsqueda.

El comportamiento de búsqueda puede especificarse prefijando nombres de campos en `search_fields` con uno de los siguientes caracteres (lo cual es equivalente a añadir `__<lookup>` al campo):

| Prefijo | Búsqueda     |                                                                                             |
| ------- | ------------ | ------------------------------------------------------------------------------------------- |
| `^`     | `istartswith` | Búsqueda que comienza con.                                                                  |
| `=`     | `iexact`       | Coincidencias exactas.                                                                      |
| `$`     | `iregex`       | Búsqueda con regex.                                                                         |
| `@`     | `search`       | Búsqueda de texto completo (Actualmente solo soportado por el [backend PostgreSQL][postgres-search] de Django). |
| Ninguno | `icontains`    | Búsqueda que contiene (Predeterminado).                                                    |

Por ejemplo:

```python
search_fields = ['=username', '=email']
```

Por defecto, el parámetro de búsqueda se llama `'search'`, pero esto puede ser sobrescrito con la configuración `SEARCH_PARAM`.

Para cambiar dinámicamente los campos de búsqueda basado en el contenido de la solicitud, es posible subclasificar `SearchFilter` y sobreescribir la función `get_search_fields()`. Por ejemplo, la siguiente subclase solo buscará en `title` si el parámetro de consulta `title_only` está en la solicitud:

```python
from rest_framework import filters

class CustomSearchFilter(filters.SearchFilter):
    def get_search_fields(self, view, request):
        if request.query_params.get('title_only'):
            return ['title']
        return super().get_search_fields(view, request)
```

Para más detalles, consulta la [documentación de Django][search-django-admin].

## OrderingFilter

La clase `OrderingFilter` soporta ordenamiento simple de resultados controlado por parámetros de consulta.

![Filtro de Ordenamiento](../img/ordering-filter.png)

Por defecto, el parámetro de consulta se llama `'ordering'`, pero esto puede ser sobrescrito con la configuración `ORDERING_PARAM`.

Por ejemplo, para ordenar usuarios por nombre de usuario:

```http
http://example.com/api/users?ordering=username
```

El cliente también puede especificar ordenamiento inverso prefijando el nombre del campo con '-', así:

```http
http://example.com/api/users?ordering=-username
```

También pueden especificarse múltiples ordenamientos:

```http
http://example.com/api/users?ordering=account,username
```

### Especificando contra qué campos se puede ordenar

Se recomienda que especifiques explícitamente qué campos la API debería permitir en el filtro de ordenamiento. Puedes hacer esto estableciendo un atributo `ordering_fields` en la vista, así:

```python
class UserListView(generics.ListAPIView):
    queryset = User.objects.all()
    serializer_class = UserSerializer
    filter_backends = [filters.OrderingFilter]
    ordering_fields = ['username', 'email']
```

Esto ayuda a prevenir fugas de datos inesperadas, como permitir a los usuarios ordenar contra un campo de hash de contraseña u otros datos sensibles.

Si _no_ especificas un atributo `ordering_fields` en la vista, la clase de filtro por defecto permitirá al usuario filtrar en cualquier campo legible en el serializador especificado por el atributo `serializer_class`.

Si estás seguro de que el queryset siendo usado por la vista no contiene datos sensibles, también puedes especificar explícitamente que una vista debería permitir ordenamiento en _cualquier_ campo del modelo o agregado del queryset, usando el valor especial `'__all__'`.

```python
class BookingsListView(generics.ListAPIView):
    queryset = Booking.objects.all()
    serializer_class = BookingSerializer
    filter_backends = [filters.OrderingFilter]
    ordering_fields = '__all__'
```

### Especificando un ordenamiento predeterminado

Si un atributo `ordering` está establecido en la vista, este se usará como el ordenamiento predeterminado.

Típicamente controlaría esto estableciendo `order_by` en el queryset inicial, pero usar el parámetro `ordering` en la vista te permite especificar el ordenamiento de una manera que luego puede ser pasado automáticamente como contexto a una plantilla renderizada. Esto hace posible renderizar automáticamente encabezados de columna de manera diferente si están siendo usados para ordenar los resultados.

```python
class UserListView(generics.ListAPIView):
    queryset = User.objects.all()
    serializer_class = UserSerializer
    filter_backends = [filters.OrderingFilter]
    ordering_fields = ['username', 'email']
    ordering = ['username']
```

El atributo `ordering` puede ser tanto una cadena como una lista/tupla de cadenas.

# Filtrado genérico personalizado

También puedes proporcionar tu propio backend de filtrado genérico, o escribir una aplicación instalable para que otros desarrolladores la usen.

Para hacerlo, sobreescribe `BaseFilterBackend`, y sobreescribe el método `.filter_queryset(self, request, queryset, view)`. El método debería devolver un nuevo queryset filtrado.

Además de permitir a los clientes realizar búsquedas y filtrado, los backends de filtro genéricos pueden ser útiles para restringir qué objetos deberían ser visibles para cualquier solicitud o usuario dado.

## Ejemplo

Por ejemplo, podrías necesitar restringir a los usuarios para que solo puedan ver los objetos que crearon.

```python
class IsOwnerFilterBackend(filters.BaseFilterBackend):
    """
    Filtro que solo permite a los usuarios ver sus propios objetos.
    """
    def filter_queryset(self, request, queryset, view):
        return queryset.filter(owner=request.user)
```

Podríamos lograr el mismo comportamiento sobreescribiendo `get_queryset()` en las vistas, pero usar un backend de filtro te permite añadir esta restricción más fácilmente a múltiples vistas, o aplicarla a través de toda la API.

## Personalizando la interfaz

Los filtros genéricos también pueden presentar una interfaz en la API navegable. Para hacerlo deberías implementar un método `to_html()` que devuelve una representación HTML renderizada del filtro. Este método debería tener la siguiente firma:

`to_html(self, request, queryset, view)`

El método debería devolver una cadena HTML renderizada.

# Paquetes de terceros

Los siguientes paquetes de terceros proporcionan implementaciones de filtro adicionales.

## Paquete Django REST framework filters

El [paquete django-rest-framework-filters][django-rest-framework-filters] funciona junto con la clase `DjangoFilterBackend`, y te permite crear fácilmente filtros a través de relaciones, o crear múltiples tipos de búsqueda de filtro para un campo dado.

## Filtro de búsqueda de palabras completas de Django REST framework

El [djangorestframework-word-filter][django-rest-framework-word-search-filter] desarrollado como alternativa a `filters.SearchFilter` que buscará palabras completas en texto, o coincidencias exactas.

## Django URL Filter

[django-url-filter][django-url-filter] proporciona una manera segura de filtrar datos a través de URLs amigables para humanos. Funciona de manera muy similar a los serializadores y campos de DRF en el sentido de que pueden estar anidados excepto que se llaman filtersets y filters. Eso proporciona una manera fácil de filtrar datos relacionados. Además, esta librería es de propósito general, por lo que puede ser usada para filtrar otras fuentes de datos y no solo los `QuerySet` de Django.

## drf-url-filters

[drf-url-filter][drf-url-filter] es una aplicación Django simple para aplicar filtros en el `Queryset` de `ModelViewSet` de DRF de una manera limpia, simple y configurable. También soporta validaciones en los parámetros de consulta entrantes y sus valores. Un hermoso paquete python `Voluptuous` está siendo usado para validaciones en los parámetros de consulta entrantes. La mejor parte de voluptuous es que puedes definir tus propias validaciones según los requisitos de tus parámetros de consulta.
