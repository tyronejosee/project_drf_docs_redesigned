# Metadatos

> [El método `OPTIONS`] permite a un cliente determinar las opciones y/o requisitos asociados con un recurso, o las capacidades de un servidor, sin implicar una acción de recurso o iniciar una recuperación de recurso.
>
> &mdash; [RFC7231, Section 4.3.7.][cite]

REST framework incluye un mecanismo configurable para determinar cómo tu API debería responder a solicitudes `OPTIONS`. Esto te permite devolver esquema de API u otra información de recursos.

Actualmente no hay convenciones ampliamente adoptadas para exactamente qué estilo de respuesta debería devolverse para solicitudes HTTP `OPTIONS`, por lo que proporcionamos un estilo ad-hoc que devuelve información útil.

Aquí hay una respuesta de ejemplo que demuestra la información que se devuelve por defecto.

```http
HTTP 200 OK
Allow: GET, POST, HEAD, OPTIONS
Content-Type: application/json
```

```json
{
  "name": "To Do List",
  "description": "List existing 'To Do' items, or create a new item.",
  "renders": ["application/json", "text/html"],
  "parses": [
    "application/json",
    "application/x-www-form-urlencoded",
    "multipart/form-data"
  ],
  "actions": {
    "POST": {
      "note": {
        "type": "string",
        "required": false,
        "read_only": false,
        "label": "title",
        "max_length": 100
      }
    }
  }
}
```

## Configuración del esquema de metadatos

Puedes establecer la clase de metadatos globalmente usando la clave de configuración `'DEFAULT_METADATA_CLASS'`:

```python
REST_FRAMEWORK = {
    'DEFAULT_METADATA_CLASS': 'rest_framework.metadata.SimpleMetadata'
}
```

O puedes establecer la clase de metadatos individualmente para una vista:

```python
class APIRoot(APIView):
    metadata_class = APIRootMetadata

    def get(self, request, format=None):
        return Response({
            ...
        })
```

El paquete REST framework solo incluye una implementación de clase de metadatos única, llamada `SimpleMetadata`. Si quieres usar un estilo alternativo, necesitarás implementar una clase de metadatos personalizada.

## Creando endpoints de esquema

Si tienes requisitos específicos para crear endpoints de esquema que son accedidos con solicitudes `GET` regulares, podrías considerar reutilizar la API de metadatos para hacerlo.

Por ejemplo, la siguiente ruta adicional podría usarse en un viewset para proporcionar un endpoint de esquema enlazable.

```python
@action(methods=['GET'], detail=False)
def api_schema(self, request):
    meta = self.metadata_class()
    data = meta.determine_metadata(request, self)
    return Response(data)
```

Hay un par de razones por las que podrías elegir tomar este enfoque, incluyendo que las respuestas `OPTIONS` [no son cacheables][no-options].

# Clases de metadatos personalizadas

Si quieres proporcionar una clase de metadatos personalizada, deberías sobreescribir `BaseMetadata` e implementar el método `determine_metadata(self, request, view)`.

Cosas útiles que podrías querer hacer podrían incluir devolver información de esquema, usando un formato como [JSON schema][json-schema], o devolver información de depuración a usuarios administradores.

## Ejemplo

La siguiente clase podría usarse para limitar la información que se devuelve a solicitudes `OPTIONS`.

```python
class MinimalMetadata(BaseMetadata):
    """
    No incluir información de campo y otra para solicitudes `OPTIONS`.
    Solo devolver el nombre y la descripción.
    """
    def determine_metadata(self, request, view):
        return {
            'name': view.get_view_name(),
            'description': view.get_view_description()
        }
```

Luego configura tu configuración para usar esta clase personalizada:

```python
REST_FRAMEWORK = {
    'DEFAULT_METADATA_CLASS': 'myproject.apps.core.MinimalMetadata'
}
```

# Paquetes de terceros

Los siguientes paquetes de terceros proporcionan implementaciones de metadatos adicionales.

## DRF-schema-adapter

[drf-schema-adapter][drf-schema-adapter] es un conjunto de herramientas que facilita proporcionar información de esquema a frameworks y librerías frontend. Proporciona un mixin de metadatos así como 2 clases de metadatos y varios adaptadores adecuados para generar [json-schema][json-schema] así como información de esquema legible por varias librerías.

También puedes escribir tu propio adaptador para trabajar con tu frontend específico.
Si deseas hacerlo, también proporciona un exportador que puede exportar esa información de esquema a archivos json.
