# Analizadores

> Los servicios web que interactúan con máquinas tienden a usar formatos más estructurados para enviar datos que codificados en formulario, ya que están enviando datos más complejos que formularios simples
>
> &mdash; Malcom Tredinnick, [Django developers group][cite]

REST framework incluye una serie de clases de Parser incorporadas, que te permiten aceptar solicitudes con varios tipos de medios. También hay soporte para definir tus propios analizadores personalizados, lo que te da la flexibilidad de diseñar los tipos de medios que tu API acepta.

## Cómo se determina el analizador

El conjunto de analizadores válidos para una vista siempre se define como una lista de clases. Cuando se accede a `request.data`, REST framework examinará el encabezado `Content-Type` en la solicitud entrante, y determinará qué analizador usar para analizar el contenido de la solicitud.

---

**Nota**: Al desarrollar aplicaciones cliente, recuerde siempre asegurarse de configurar el encabezado `Content-Type` al enviar datos en una solicitud HTTP.

Si no configura el tipo de contenido, la mayoría de los clientes usarán por defecto `'application/x-www-form-urlencoded'`, que puede no ser lo que deseaba.

Por ejemplo, si está enviando datos codificados en `json` usando jQuery con el [método .ajax()][jquery-ajax], debe asegurarse de incluir la configuración `contentType: 'application/json'`.

---

## Configuración de los analizadores

El conjunto predeterminado de analizadores se puede configurar globalmente usando la configuración `DEFAULT_PARSER_CLASSES`. Por ejemplo, las siguientes configuraciones permitirían solo solicitudes con contenido `JSON`, en lugar del valor predeterminado de JSON o datos de formulario.

```python
REST_FRAMEWORK = {
    'DEFAULT_PARSER_CLASSES': [
        'rest_framework.parsers.JSONParser',
    ]
}
```

También puede configurar los analizadores utilizados para una vista individual o viewset,
usando las vistas basadas en clases `APIView`.

```python
from rest_framework.parsers import JSONParser
from rest_framework.response import Response
from rest_framework.views import APIView

class ExampleView(APIView):
    """
    Una vista que puede aceptar solicitudes POST con contenido JSON.
    """
    parser_classes = [JSONParser]

    def post(self, request, format=None):
        return Response({'received data': request.data})
```

O si está usando el decorador `@api_view` con vistas basadas en funciones.

```python
from rest_framework.decorators import api_view
from rest_framework.decorators import parser_classes
from rest_framework.parsers import JSONParser

@api_view(['POST'])
@parser_classes([JSONParser])
def example_view(request, format=None):
    """
    Una vista que puede aceptar solicitudes POST con contenido JSON.
    """
    return Response({'received data': request.data})
```

# Referencia de la API

## JSONParser

Analiza el contenido de la solicitud `JSON`. `request.data` se llenará con un diccionario de datos.

**.media_type**: `application/json`

## FormParser

Analiza el contenido de formularios HTML. `request.data` se llenará con un `QueryDict` de datos.

Normalmente querrá usar tanto `FormParser` como `MultiPartParser` juntos para soportar completamente los datos de formularios HTML.

**.media_type**: `application/x-www-form-urlencoded`

## MultiPartParser

Analiza el contenido de formularios HTML multiparte, que soporta la subida de archivos. `request.data` y `request.FILES` se llenarán con un `QueryDict` y `MultiValueDict` respectivamente.

Normalmente querrá usar tanto `FormParser` como `MultiPartParser` juntos para soportar completamente los datos de formularios HTML.

**.media_type**: `multipart/form-data`

## FileUploadParser

Analiza el contenido de subida de archivos sin procesar. La propiedad `request.data` será un diccionario con una única clave `'file'` que contiene el archivo subido.

Si la vista usada con `FileUploadParser` es llamada con un argumento de URL `filename`, entonces ese argumento se usará como el nombre del archivo.

Si es llamada sin un argumento de URL `filename`, entonces el cliente debe establecer el nombre del archivo en el encabezado HTTP `Content-Disposition`. Por ejemplo `Content-Disposition: attachment; filename=upload.jpg`.

**.media_type**: `*/*`

##### Notas:

- El `FileUploadParser` es para uso con clientes nativos que pueden subir el archivo como una solicitud de datos sin procesar. Para subidas basadas en web, o para clientes nativos con soporte de subida multiparte, debería usar `MultiPartParser` en su lugar.
- Dado que el `media_type` de este analizador coincide con cualquier tipo de contenido, `FileUploadParser` generalmente debería ser el único analizador configurado en una vista de API.
- `FileUploadParser` respeta la configuración estándar de Django `FILE_UPLOAD_HANDLERS` y el atributo `request.upload_handlers`. Vea la [documentación de Django][upload-handlers] para más detalles.

##### Ejemplo de uso básico:

```python
# views.py
class FileUploadView(views.APIView):
    parser_classes = [FileUploadParser]

    def put(self, request, filename, format=None):
        file_obj = request.data['file']
        # ...
        # hacer algo con el archivo subido
        # ...
        return Response(status=204)

# urls.py
urlpatterns = [
    # ...
    re_path(r'^upload/(?P<filename>[^/]+)$', FileUploadView.as_view())
]
```

# Analizadores personalizados

Para implementar un analizador personalizado, debe sobreescribir `BaseParser`, establecer la propiedad `.media_type` e implementar el método `.parse(self, stream, media_type, parser_context)`.

El método debe devolver los datos que se usarán para llenar la propiedad `request.data`.

Los argumentos pasados a `.parse()` son:

### stream

Un objeto similar a un stream que representa el cuerpo de la solicitud.

### media_type

Opcional. Si se proporciona, este es el tipo de medio del contenido de la solicitud entrante.

Dependiendo del encabezado `Content-Type:` de la solicitud, esto puede ser más específico que el atributo `media_type` del renderizador, y puede incluir parámetros de tipo de medio. Por ejemplo `"text/plain; charset=utf-8"`.

### parser_context

Opcional. Si se proporciona, este argumento será un diccionario que contiene cualquier contexto adicional que pueda ser necesario para analizar el contenido de la solicitud.

Por defecto esto incluirá las siguientes claves: `view`, `request`, `args`, `kwargs`.

## Ejemplo

El siguiente es un ejemplo de analizador de texto plano que llenará la propiedad `request.data` con una cadena que representa el cuerpo de la solicitud.

```python
class PlainTextParser(BaseParser):
    """
    Analizador de texto plano.
    """
    media_type = 'text/plain'

    def parse(self, stream, media_type=None, parser_context=None):
        """
        Simplemente devuelve una cadena que representa el cuerpo de la solicitud.
        """
        return stream.read()
```

# Paquetes de terceros

Los siguientes paquetes de terceros también están disponibles.

## YAML

[REST framework YAML][rest-framework-yaml] proporciona soporte de análisis y renderizado [YAML][yaml]. Anteriormente se incluía directamente en el paquete REST framework, y ahora se admite como un paquete de terceros.

#### Instalación y configuración

Instale usando pip.

```bash
pip install djangorestframework-yaml
```

Modifique su configuración de REST framework.

```python
REST_FRAMEWORK = {
    'DEFAULT_PARSER_CLASSES': [
        'rest_framework_yaml.parsers.YAMLParser',
    ],
    'DEFAULT_RENDERER_CLASSES': [
        'rest_framework_yaml.renderers.YAMLRenderer',
    ],
}
```

## XML

[REST Framework XML][rest-framework-xml] proporciona un formato XML simple e informal. Anteriormente se incluía directamente en el paquete REST framework, y ahora se admite como un paquete de terceros.

#### Instalación y configuración

Instale usando pip.

```bash
pip install djangorestframework-xml
```

Modifique su configuración de REST framework.

```python
REST_FRAMEWORK = {
    'DEFAULT_PARSER_CLASSES': [
        'rest_framework_xml.parsers.XMLParser',
    ],
    'DEFAULT_RENDERER_CLASSES': [
        'rest_framework_xml.renderers.XMLRenderer',
    ],
}
```

## MessagePack

[MessagePack][messagepack] es un formato de serialización binaria rápido y eficiente. [Juan Riaza][juanriaza] mantiene el paquete [djangorestframework-msgpack][djangorestframework-msgpack] que proporciona soporte de renderizador y analizador MessagePack para REST framework.

## CamelCase JSON

[djangorestframework-camel-case] proporciona renderizadores y analizadores JSON en camel case para REST framework. Esto permite que los serializadores usen nombres de campo con guiones bajos al estilo Python, pero se expongan en la API como nombres de campo en camel case al estilo Javascript. Es mantenido por [Vitaly Babiy][vbabiy].
