# Solicitudes

> Si estás haciendo cosas de servicio web basado en REST ... deberías ignorar request.POST.
>
> &mdash; Malcom Tredinnick, [Django developers group][cite]

La clase `Request` de REST framework extiende el `HttpRequest` estándar, añadiendo soporte para el análisis flexible de solicitudes y autenticación de solicitudes de REST framework.

---

# Análisis de solicitudes

Los objetos Request de REST framework proporcionan análisis flexible de solicitudes que te permite tratar solicitudes con datos JSON u otros tipos de medios de la misma manera que normalmente tratarías datos de formulario.

## .data

`request.data` devuelve el contenido analizado del cuerpo de la solicitud. Esto es similar a los atributos estándar `request.POST` y `request.FILES` excepto que:

- Incluye todo el contenido analizado, incluyendo entradas de _archivo y no archivo_.
- Soporta el análisis del contenido de métodos HTTP distintos de `POST`, lo que significa que puedes acceder al contenido de solicitudes `PUT` y `PATCH`.
- Soporta el análisis flexible de solicitudes de REST framework, en lugar de solo soportar datos de formulario. Por ejemplo, puedes manejar [datos JSON] entrantes de manera similar a como manejas [datos de formulario] entrantes.

Para más detalles consulta la [documentación de analizadores].

## .query_params

`request.query_params` es un sinónimo con un nombre más correcto para `request.GET`.

Para mayor claridad en tu código, recomendamos usar `request.query_params` en lugar del `request.GET` estándar de Django. Hacerlo ayudará a mantener tu base de código más correcta y obvia - cualquier tipo de método HTTP puede incluir parámetros de consulta, no solo solicitudes `GET`.

## .parsers

La clase `APIView` o el decorador `@api_view` asegurarán que esta propiedad se establezca automáticamente en una lista de instancias de `Parser`, basándose en las `parser_classes` establecidas en la vista o en la configuración `DEFAULT_PARSER_CLASSES`.

Normalmente no necesitarás acceder a esta propiedad.

---

**Nota:** Si un cliente envía contenido malformado, al acceder a `request.data` puede lanzarse una `ParseError`. Por defecto, la clase `APIView` o el decorador `@api_view` de REST framework capturarán el error y devolverán una respuesta `400 Bad Request`.

Si un cliente envía una solicitud con un tipo de contenido que no puede ser analizado, se lanzará una excepción `UnsupportedMediaType`, que por defecto será capturada y devolverá una respuesta `415 Unsupported Media Type`.

# Negociación de contenido

La solicitud expone algunas propiedades que te permiten determinar el resultado de la etapa de negociación de contenido. Esto te permite implementar comportamientos como seleccionar diferentes esquemas de serialización para diferentes tipos de medios.

## .accepted_renderer

La instancia del renderizador que fue seleccionada por la etapa de negociación de contenido.

## .accepted_media_type

Una cadena que representa el tipo de medio que fue aceptado por la etapa de negociación de contenido.

# Autenticación

REST framework proporciona autenticación flexible por solicitud, que te da la capacidad de:

- Usar diferentes políticas de autenticación para diferentes partes de tu API.
- Soportar el uso de múltiples políticas de autenticación.
- Proporcionar tanto información de usuario como de token asociada con la solicitud entrante.

## .user

`request.user` típicamente devuelve una instancia de `django.contrib.auth.models.User`, aunque el comportamiento depende de la política de autenticación being utilizada.

Si la solicitud no está autenticada, el valor predeterminado de `request.user` es una instancia de `django.contrib.auth.models.AnonymousUser`.

Para más detalles consulta la [documentación de autenticación].

## .auth

`request.auth` devuelve cualquier contexto de autenticación adicional. El comportamiento exacto de `request.auth` depende de la política de autenticación being utilizada, pero típicamente puede ser una instancia del token contra el cual fue autenticada la solicitud.

Si la solicitud no está autenticada, o si no hay contexto adicional presente, el valor predeterminado de `request.auth` es `None`.

Para más detalles consulta la [documentación de autenticación].

## .authenticators

La clase `APIView` o el decorador `@api_view` asegurarán que esta propiedad se establezca automáticamente en una lista de instancias de `Authentication`, basándose en las `authentication_classes` establecidas en la vista o en la configuración `DEFAULT_AUTHENTICATORS`.

Normalmente no necesitarás acceder a esta propiedad.

---

**Nota:** Puedes ver un `WrappedAttributeError` lanzado al llamar a las propiedades `.user` o `.auth`. Estos errores se originan en un autenticador como un `AttributeError` estándar, sin embargo, es necesario que se relancen como un tipo de excepción diferente para evitar que sean suprimidos por el acceso a la propiedad externa. Python no reconocerá que el `AttributeError` se origina en el autenticador y en su lugar asumirá que el objeto de solicitud no tiene una propiedad `.user` o `.auth`. El autenticador necesitará ser corregido.

# Mejoras del navegador

REST framework soporta algunas mejoras del navegador como formularios `PUT`, `PATCH` y `DELETE` basados en navegador.

## .method

`request.method` devuelve la representación en cadena **en mayúsculas** del método HTTP de la solicitud.

Los formularios `PUT`, `PATCH` y `DELETE` basados en navegador son soportados de forma transparente.

Para más información consulta la [documentación de mejoras del navegador].

## .content_type

`request.content_type` devuelve un objeto de cadena que representa el tipo de medio del cuerpo de la solicitud HTTP, o una cadena vacía si no se proporcionó ningún tipo de medio.

Normalmente no necesitarás acceder directamente al tipo de contenido de la solicitud, ya que normalmente dependerás del comportamiento de análisis de solicitudes predeterminado de REST framework.

Si necesitas acceder al tipo de contenido de la solicitud, deberías usar la propiedad `.content_type` en lugar de usar `request.META.get('HTTP_CONTENT_TYPE')`, ya que proporciona soporte transparente para contenido no basado en formularios del navegador.

Para más información consulta la [documentación de mejoras del navegador].

## .stream

`request.stream` devuelve un flujo que representa el contenido del cuerpo de la solicitud.

Normalmente no necesitarás acceder directamente al contenido de la solicitud, ya que normalmente dependerás del comportamiento de análisis de solicitudes predeterminado de REST framework.

---

# Atributos estándar de HttpRequest

Como el `Request` de REST framework extiende el `HttpRequest` de Django, todos los otros atributos y métodos estándar también están disponibles. Por ejemplo, los diccionarios `request.META` y `request.session` están disponibles de forma normal.

Ten en cuenta que por razones de implementación la clase `Request` no hereda de la clase `HttpRequest`, sino que extiende la clase usando composición.
