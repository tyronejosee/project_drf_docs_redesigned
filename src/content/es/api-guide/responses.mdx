# Respuestas

> A diferencia de los objetos HttpResponse básicos, los objetos TemplateResponse retienen los detalles del contexto que fue proporcionado por la vista para calcular la respuesta. La salida final de la respuesta no se calcula hasta que es necesaria, más tarde en el proceso de respuesta.
>
> &mdash; [Django documentation][cite]

REST framework soporta la negociación de contenido HTTP proporcionando una clase `Response` que te permite devolver contenido que puede ser renderizado en múltiples tipos de contenido, dependiendo de la solicitud del cliente.

La clase `Response` hereda de `SimpleTemplateResponse` de Django. Los objetos `Response` se inicializan con datos, que deben consistir en primitivas nativas de Python. REST framework luego usa la negociación de contenido HTTP estándar para determinar cómo debe renderizar el contenido final de la respuesta.

No hay ningún requisito para que uses la clase `Response`, también puedes devolver objetos `HttpResponse` o `StreamingHttpResponse` regulares desde tus vistas si es necesario. Usar la clase `Response` simplemente proporciona una interfaz más agradable para devolver respuestas de Web API negociadas de contenido, que pueden ser renderizadas en múltiples formatos.

A menos que quieras personalizar fuertemente REST framework por alguna razón, siempre deberías usar una clase `APIView` o función `@api_view` para vistas que devuelven objetos `Response`. Hacerlo asegura que la vista pueda realizar negociación de contenido y seleccionar el renderizador apropiado para la respuesta, antes de que sea devuelta desde la vista.

# Creando respuestas

## Response()

**Firma:** `Response(data, status=None, template_name=None, headers=None, content_type=None)`

A diferencia de los objetos `HttpResponse` regulares, no instancias objetos `Response` con contenido renderizado. En su lugar, pasas datos no renderizados, que pueden consistir en cualquier primitiva de Python.

Los renderizadores usados por la clase `Response` no pueden manejar nativamente tipos de datos complejos como las instancias de modelos de Django, por lo que necesitas serializar los datos en tipos de datos primitivos antes de crear el objeto `Response`.

Puedes usar las clases `Serializer` de REST framework para realizar esta serialización de datos, o usar tu propia serialización personalizada.

Argumentos:

- `data`: Los datos serializados para la respuesta.
- `status`: Un código de estado para la respuesta. El valor predeterminado es 200. Ver también [códigos de estado][statuscodes].
- `template_name`: Un nombre de plantilla para usar si se selecciona `HTMLRenderer`.
- `headers`: Un diccionario de encabezados HTTP para usar en la respuesta.
- `content_type`: El tipo de contenido de la respuesta. Normalmente, esto será establecido automáticamente por el renderizador según lo determine la negociación de contenido, pero puede haber algunos casos donde necesites especificar el tipo de contenido explícitamente.

# Attributes

## .data

Los datos serializados no renderizados de la respuesta.

## .status_code

El código de estado numérico de la respuesta HTTP.

## .content

El contenido renderizado de la respuesta. El método `.render()` debe haber sido llamado antes de que `.content` pueda ser accedido.

## .template_name

El `template_name`, si se proporcionó. Solo se requiere si `HTMLRenderer` o algún otro renderizador de plantillas personalizado es el renderizador aceptado para la respuesta.

## .accepted_renderer

La instancia del renderizador que se usará para renderizar la respuesta.

Establecido automáticamente por `APIView` o `@api_view` inmediatamente antes de que la respuesta sea devuelta desde la vista.

## .accepted_media_type

El tipo de medio que fue seleccionado por la etapa de negociación de contenido.

Establecido automáticamente por `APIView` o `@api_view` inmediatamente antes de que la respuesta sea devuelta desde la vista.

## .renderer_context

Un diccionario de información de contexto adicional que será pasada al método `.render()` del renderizador.

Establecido automáticamente por `APIView` o `@api_view` inmediatamente antes de que la respuesta sea devuelta desde la vista.

# Atributos estándar de HttpResponse

La clase `Response` extiende `SimpleTemplateResponse`, y todos los atributos y métodos habituales también están disponibles en la respuesta. Por ejemplo, puedes establecer encabezados en la respuesta de la manera estándar:

```python
response = Response()
response['Cache-Control'] = 'no-cache'
```

## .render()

**Firma:** `.render()`

Al igual que con cualquier otro `TemplateResponse`, este método es llamado para renderizar los datos serializados de la respuesta en el contenido final de la respuesta. Cuando se llama a `.render()`, el contenido de la respuesta se establecerá al resultado de llamar al método `.render(data, accepted_media_type, renderer_context)` en la instancia `accepted_renderer`.

Normalmente no necesitarás llamar a `.render()` tú mismo, ya que es manejado por el ciclo de respuesta estándar de Django.
