# Configuración

> Los espacios de nombres son una gran idea - ¡hagamos más de esos!
>
> &mdash; [El Zen de Python][cite]

La configuración para REST framework está toda dentro de un solo espacio de nombres de Django, llamado `REST_FRAMEWORK`.

Por ejemplo, el archivo `settings.py` de tu proyecto podría incluir algo como esto:

```python
REST_FRAMEWORK = {
    'DEFAULT_RENDERER_CLASSES': [
        'rest_framework.renderers.JSONRenderer',
    ],
    'DEFAULT_PARSER_CLASSES': [
        'rest_framework.parsers.JSONParser',
    ]
}
```

## Accediendo a la configuración

Si necesitas acceder a los valores de la configuración de la API de REST framework en tu proyecto,
deberías usar el objeto `api_settings`. Por ejemplo:

```python
from rest_framework.settings import api_settings

print(api_settings.DEFAULT_AUTHENTICATION_CLASSES)
```

El objeto `api_settings` verificará cualquier configuración definida por el usuario, y de lo contrario volverá a los valores predeterminados. Cualquier configuración que use rutas de importación de cadenas para referirse a una clase importará y devolverá automáticamente la clase referenciada, en lugar de la cadena literal.

# Referencia de la API

## Configuración de la política de la API

_Las siguientes configuraciones controlan las políticas básicas de la API, y se aplican a cada vista basada en clases `APIView`, o vista basada en funciones `@api_view`._

#### DEFAULT_RENDERER_CLASSES

Una lista o tupla de clases de renderizador, que determina el conjunto predeterminado de renderizadores que pueden usarse al devolver un objeto `Response`.

Predeterminado:

```python
[
    'rest_framework.renderers.JSONRenderer',
    'rest_framework.renderers.BrowsableAPIRenderer',
]
```

#### DEFAULT_PARSER_CLASSES

Una lista o tupla de clases de analizador, que determina el conjunto predeterminado de analizadores usados al acceder a la propiedad `request.data`.

Predeterminado:

```python
[
    'rest_framework.parsers.JSONParser',
    'rest_framework.parsers.FormParser',
    'rest_framework.parsers.MultiPartParser'
]
```

#### DEFAULT_AUTHENTICATION_CLASSES

Una lista o tupla de clases de autenticación, que determina el conjunto predeterminado de autenticadores usados al acceder a las propiedades `request.user` o `request.auth`.

Predeterminado:

```python
[
    'rest_framework.authentication.SessionAuthentication',
    'rest_framework.authentication.BasicAuthentication'
]
```

#### DEFAULT_PERMISSION_CLASSES

Una lista o tupla de clases de permisos, que determina el conjunto predeterminado de permisos verificados al inicio de una vista. El permiso debe ser concedido por cada clase en la lista.

Predeterminado:

```python
[
    'rest_framework.permissions.AllowAny',
]
```

#### DEFAULT_THROTTLE_CLASSES

Una lista o tupla de clases de estrangulación, que determina el conjunto predeterminado de estrangulaciones verificadas al inicio de una vista.

Predeterminado: `[]`

#### DEFAULT_CONTENT_NEGOTIATION_CLASS

Una clase de negociación de contenido, que determina cómo se selecciona un renderizador para la respuesta, dada una solicitud entrante.

Predeterminado: `'rest_framework.negotiation.DefaultContentNegotiation'`

#### DEFAULT_SCHEMA_CLASS

Una clase de inspector de vistas que se usará para la generación de esquemas.

Predeterminado: `'rest_framework.schemas.openapi.AutoSchema'`

## Configuración de vistas genéricas

_Las siguientes configuraciones controlan el comportamiento de las vistas genéricas basadas en clases._

#### DEFAULT_FILTER_BACKENDS

Una lista de clases de backend de filtro que deberían usarse para filtrado genérico.
Si se establece en `None` entonces el filtrado genérico está deshabilitado.

#### DEFAULT_PAGINATION_CLASS

La clase predeterminada a usar para la paginación de queryset. Si se establece en `None`, la paginación
está deshabilitada por defecto. Ver la documentación de paginación para más orientación sobre
[establecer](pagination.md#setting-the-pagination-style) y
[modificar](pagination.md#modifying-the-pagination-style) el estilo de paginación.

Predeterminado: `None`

#### PAGE_SIZE

El tamaño de página predeterminado a usar para la paginación. Si se establece en `None`, la paginación está deshabilitada por defecto.

Predeterminado: `None`

### SEARCH_PARAM

El nombre de un parámetro de consulta, que puede usarse para especificar el término de búsqueda usado por `SearchFilter`.

Predeterminado: `search`

#### ORDERING_PARAM

El nombre de un parámetro de consulta, que puede usarse para especificar el ordenamiento de resultados devueltos por `OrderingFilter`.

Predeterminado: `ordering`

## Configuración de versionamiento

#### DEFAULT_VERSION

El valor que debería usarse para `request.version` cuando no hay información de versionamiento presente.

Predeterminado: `None`

#### ALLOWED_VERSIONS

Si se establece, este valor restringirá el conjunto de versiones que pueden ser devueltas por el esquema de versionamiento, y lanzará un error si la versión proporcionada no está en este conjunto.

Predeterminado: `None`

#### VERSION_PARAM

La cadena que debería usarse para cualquier parámetro de versionamiento, como en el tipo de medio o parámetros de consulta de URL.

Predeterminado: `'version'`

#### DEFAULT_VERSIONING_CLASS

El esquema de versionamiento predeterminado a usar.

Predeterminado: `None`

## Configuración de autenticación

_Las siguientes configuraciones controlan el comportamiento de solicitudes no autenticadas._

#### UNAUTHENTICATED_USER

La clase que debería usarse para inicializar `request.user` para solicitudes no autenticadas.
(Si se elimina completamente la autenticación, ej. al eliminar `django.contrib.auth` de
`INSTALLED_APPS`, establece `UNAUTHENTICATED_USER` a `None`.)

Predeterminado: `django.contrib.auth.models.AnonymousUser`

#### UNAUTHENTICATED_TOKEN

La clase que debería usarse para inicializar `request.auth` para solicitudes no autenticadas.

Predeterminado: `None`

## Configuración de pruebas

_Las siguientes configuraciones controlan el comportamiento de APIRequestFactory y APIClient_

#### TEST_REQUEST_DEFAULT_FORMAT

El formato predeterminado que debería usarse al hacer solicitudes de prueba.

Esto debería coincidir con el formato de una de las clases de renderizador en la configuración `TEST_REQUEST_RENDERER_CLASSES`.

Predeterminado: `'multipart'`

#### TEST_REQUEST_RENDERER_CLASSES

Las clases de renderizador que son compatibles al construir solicitudes de prueba.

El formato de cualquiera de estas clases de renderizador puede usarse al construir una solicitud de prueba, por ejemplo: `client.post('/users', {'username': 'jamie'}, format='json')`

Predeterminado:

```python
[
    'rest_framework.renderers.MultiPartRenderer',
    'rest_framework.renderers.JSONRenderer'
]
```

## Controles de generación de esquemas

#### SCHEMA_COERCE_PATH_PK

Si se establece, esto mapea el identificador `'pk'` en la configuración de URL al nombre de campo real
al generar un parámetro de ruta de esquema. Típicamente esto será `'id'`.
Esto da una representación más adecuada ya que "clave primaria" es un detalle de implementación,
mientras que "identificador" es un concepto más general.

Predeterminado: `True`

#### SCHEMA_COERCE_METHOD_NAMES

Si se establece, esto se usa para mapear nombres de métodos internos de viewset a nombres de acción externos
usados en la generación de esquemas. Esto nos permite generar nombres que
son más adecuados para una representación externa que los que se usan
internamente en la base de código.

Predeterminado: `{'retrieve': 'read', 'destroy': 'delete'}`

## Controles de tipo de contenido

#### URL_FORMAT_OVERRIDE

El nombre de un parámetro de URL que puede usarse para sobrescribir el comportamiento del encabezado `Accept` de negociación de contenido predeterminado, usando un parámetro de consulta `format=…` en la URL de solicitud.

Por ejemplo: `http://example.com/organizations/?format=csv`

Si el valor de esta configuración es `None` entonces las sobrescrituras de formato de URL estarán deshabilitadas.

Predeterminado: `'format'`

#### FORMAT_SUFFIX_KWARG

El nombre de un parámetro en la configuración de URL que puede usarse para proporcionar un sufijo de formato. Esta configuración se aplica al usar `format_suffix_patterns` para incluir patrones de URL con sufijo.

Por ejemplo: `http://example.com/organizations.csv/`

Predeterminado: `'format'`

## Formato de fecha y hora

_Las siguientes configuraciones se usan para controlar cómo pueden analizarse y renderizarse las representaciones de fecha y hora._

#### DATETIME_FORMAT

Una cadena de formato que debería usarse por defecto para renderizar la salida de campos de serializador `DateTimeField`. Si es `None`, entonces los campos de serializador `DateTimeField` devolverán objetos `datetime` de Python, y la codificación de datetime será determinada por el renderizador.

Puede ser cualquiera de `None`, `'iso-8601'` o una cadena de formato [strftime de Python][strftime].

Predeterminado: `'iso-8601'`

#### DATETIME_INPUT_FORMATS

Una lista de cadenas de formato que deberían usarse por defecto para analizar entradas a campos de serializador `DateTimeField`.

Puede ser una lista incluyendo la cadena `'iso-8601'` o cadenas de formato [strftime de Python][strftime].

Predeterminado: `['iso-8601']`

#### DATE_FORMAT

Una cadena de formato que debería usarse por defecto para renderizar la salida de campos de serializador `DateField`. Si es `None`, entonces los campos de serializador `DateField` devolverán objetos `date` de Python, y la codificación de fecha será determinada por el renderizador.

Puede ser cualquiera de `None`, `'iso-8601'` o una cadena de formato [strftime de Python][strftime].

Predeterminado: `'iso-8601'`

#### DATE_INPUT_FORMATS

Una lista de cadenas de formato que deberían usarse por defecto para analizar entradas a campos de serializador `DateField`.

Puede ser una lista incluyendo la cadena `'iso-8601'` o cadenas de formato [strftime de Python][strftime].

Predeterminado: `['iso-8601']`

#### TIME_FORMAT

Una cadena de formato que debería usarse por defecto para renderizar la salida de campos de serializador `TimeField`. Si es `None`, entonces los campos de serializador `TimeField` devolverán objetos `time` de Python, y la codificación de hora será determinada por el renderizador.

Puede ser cualquiera de `None`, `'iso-8601'` o una cadena de formato [strftime de Python][strftime].

Predeterminado: `'iso-8601'`

#### TIME_INPUT_FORMATS

Una lista de cadenas de formato que deberían usarse por defecto para analizar entradas a campos de serializador `TimeField`.

Puede ser una lista incluyendo la cadena `'iso-8601'` o cadenas de formato [strftime de Python][strftime].

Predeterminado: `['iso-8601']`

## Codificaciones

#### UNICODE_JSON

Cuando se establece en `True`, las respuestas JSON permitirán caracteres unicode en las respuestas. Por ejemplo:

```json
{ "unicode black star": "★" }
```

Cuando se establece en `False`, las respuestas JSON escaparán caracteres no ascii, así:

```json
{ "unicode black star": "\u2605" }
```

Ambos estilos se conforman a [RFC 4627][rfc4627], y son JSON sintácticamente válidos. El estilo unicode es preferido como más amigable para el usuario al inspeccionar respuestas de API.

Predeterminado: `True`

#### COMPACT_JSON

Cuando se establece en `True`, las respuestas JSON devolverán representaciones compactas, sin espaciado después de los caracteres `':'` y `','`. Por ejemplo:

```json
{ "is_admin": false, "email": "jane@example" }
```

Cuando se establece en `False`, las respuestas JSON devolverán representaciones ligeramente más verbosas, así:

```json
{ "is_admin": false, "email": "jane@example" }
```

El estilo predeterminado es devolver respuestas minimizadas, en línea con las [directrices de diseño de API de Heroku][heroku-minified-json].

Predeterminado: `True`

#### STRICT_JSON

Cuando se establece en `True`, el renderizado y análisis de JSON solo observará JSON sintácticamente válido, lanzando una excepción para los valores de flotante extendidos (`nan`, `inf`, `-inf`) aceptados por el módulo `json` de Python. Esta es la configuración recomendada, ya que estos valores generalmente no son compatibles. ej., ni el `JSON.Parse` de Javascript ni el tipo de dato JSON de PostgreSQL aceptan estos valores.

Cuando se establece en `False`, el renderizado y análisis de JSON será permisivo. Sin embargo, estos valores siguen siendo inválidos y necesitarán ser manejados especialmente en tu código.

Predeterminado: `True`

#### COERCE_DECIMAL_TO_STRING

Al devolver objetos decimales en representaciones de API que no soportan un tipo decimal nativo, normalmente es mejor devolver el valor como una cadena. Esto evita la pérdida de precisión que ocurre con las implementaciones de punto flotante binario.

Cuando se establece en `True`, la clase de serializador `DecimalField` devolverá cadenas en lugar de objetos `Decimal`. Cuando se establece en `False`, los serializadores devolverán objetos `Decimal`, que el codificador JSON predeterminado devolverá como flotantes.

Predeterminado: `True`

## Nombres y descripciones de vistas

**Las siguientes configuraciones se usan para generar los nombres y descripciones de vistas, como se usan en respuestas a solicitudes `OPTIONS`, y como se usan en la API navegable.**

#### VIEW_NAME_FUNCTION

Una cadena que representa la función que debería usarse al generar nombres de vista.

Esto debería ser una función con la siguiente firma:

```python
view_name(self)
```

- `self`: La instancia de vista. Típicamente la función de nombre inspeccionaría el nombre de la clase al generar un nombre descriptivo, accediendo a `self.__class__.__name__`.

Si la instancia de vista hereda `ViewSet`, puede haber sido inicializada con varios argumentos opcionales:

- `name`: Un nombre explícitamente proporcionado a una vista en el viewset. Típicamente, este valor debería usarse tal como está cuando se proporciona.
- `suffix`: Texto usado al diferenciar vistas individuales en un viewset. Este argumento es mutuamente exclusivo con `name`.
- `detail`: Booleano que diferencia una vista individual en un viewset como siendo una vista 'list' o 'detail'.

Predeterminado: `'rest_framework.views.get_view_name'`

#### VIEW_DESCRIPTION_FUNCTION

Una cadena que representa la función que debería usarse al generar descripciones de vista.

Esta configuración puede cambiarse para soportar estilos de marcado diferentes al markdown predeterminado. Por ejemplo, puedes usarla para soportar marcado `rst` en las cadenas de documentación de vista siendo salida en la API navegable.

Esto debería ser una función con la siguiente firma:

```python
view_description(self, html=False)
```

- `self`: La instancia de vista. Típicamente la función de descripción inspeccionaría la cadena de documentación de la clase al generar una descripción, accediendo a `self.__class__.__doc__`
- `html`: Un booleano que indica si se requiere salida HTML. `True` cuando se usa en la API navegable, y `False` cuando se usa en generar respuestas `OPTIONS`.

Si la instancia de vista hereda `ViewSet`, puede haber sido inicializada con varios argumentos opcionales:

- `description`: Una descripción explícitamente proporcionada a la vista en el viewset. Típicamente, esto es establecido por acciones adicionales de viewset, y debería usarse tal como está.

Predeterminado: `'rest_framework.views.get_view_description'`

Configuraciones globales para [límites de campo de selección para renderizar campos relacionales](relations.md#select-field-cutoffs) en la API navegable.

## Configuraciones misceláneas

#### EXCEPTION_HANDLER

Una cadena que representa la función que debería usarse al devolver una respuesta para cualquier excepción dada. Si la función devuelve `None`, se lanzará un error 500.

Esta configuración puede cambiarse para soportar respuestas de error diferentes de las respuestas predeterminadas `{"detail": "Fallo..."}`. Por ejemplo, puedes usarla para proporcionar respuestas de API como `{"errors": [{"message": "Fallo...", "code": ""} ...]}`.

Esto debería ser una función con la siguiente firma:

```python
exception_handler(exc, context)
```

- `exc`: La excepción.

Predeterminado: `'rest_framework.views.exception_handler'`

#### NON_FIELD_ERRORS_KEY

Una cadena que representa la clave que debería usarse para errores de serializador que no se refieren a un campo específico, sino que son errores generales.

Predeterminado: `'non_field_errors'`

#### URL_FIELD_NAME

Una cadena que representa la clave que debería usarse para los campos de URL generados por `HyperlinkedModelSerializer`.

Predeterminado: `'url'`

#### NUM_PROXIES

Un entero de 0 o más, que puede usarse para especificar el número de proxies de aplicación detrás de los cuales se ejecuta la API. Esto permite que la estrangulación identifique más precisamente las direcciones IP del cliente. Si se establece en `None` entonces se usará coincidencia de IP menos estricta por las clases de estrangulación.

Predeterminado: `None`
