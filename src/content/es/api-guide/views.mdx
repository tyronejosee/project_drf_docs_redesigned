# Vistas Basadas en Clases

> Las vistas basadas en clases de Django son una bienvenida desviación del estilo antiguo de vistas.
>
> &mdash; [Reinout van Rees][cite]

REST framework proporciona una clase `APIView`, que hereda de la clase `View` de Django.

Las clases `APIView` son diferentes de las clases `View` regulares de las siguientes maneras:

- Las solicitudes pasadas a los métodos del manejador serán instancias de `Request` de REST framework, no instancias de `HttpRequest` de Django.
- Los métodos del manejador pueden devolver `Response` de REST framework, en lugar de `HttpResponse` de Django. La vista gestionará la negociación de contenido y establecerá el renderizador correcto en la respuesta.
- Cualquier excepción `APIException` será capturada y mediada en respuestas apropiadas.
- Las solicitudes entrantes serán autenticadas y se ejecutarán las verificaciones de permisos y/o estrangulación apropiadas antes de despachar la solicitud al método del manejador.

Usar la clase `APIView` es casi lo mismo que usar una clase `View` regular, como de costumbre, la solicitud entrante se despacha a un método del manejador apropiado como `.get()` o `.post()`. Además, se pueden establecer varios atributos en la clase que controlan varios aspectos de la política de la API.

Por ejemplo:

```python
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import authentication, permissions
from django.contrib.auth.models import User

class ListUsers(APIView):
    """
    Vista para listar todos los usuarios en el sistema.

    * Requiere autenticación por token.
    * Solo los usuarios administradores pueden acceder a esta vista.
    """
    authentication_classes = [authentication.TokenAuthentication]
    permission_classes = [permissions.IsAdminUser]

    def get(self, request, format=None):
        """
        Devuelve una lista de todos los usuarios.
        """
        usernames = [user.username for user in User.objects.all()]
        return Response(usernames)
```

**Nota**: Los métodos completos, atributos y relaciones entre `APIView`, `GenericAPIView`, varios `Mixins` y `Viewsets` de Django REST Framework pueden ser inicialmente complejos. Además de la documentación aquí, el recurso [Classy Django REST Framework][classy-drf] proporciona una referencia navegable, con métodos y atributos completos, para cada una de las vistas basadas en clases de Django REST Framework.

## Métodos de instanciación de la política de la API

Los siguientes métodos son utilizados por REST framework para instanciar las varias políticas conectables de la API. Normalmente no necesitarás sobrescribir estos métodos.

### .get_renderers(self)

### .get_parsers(self)

### .get_authenticators(self)

### .get_throttles(self)

### .get_permissions(self)

### .get_content_negotiator(self)

### .get_exception_handler(self)

## Métodos de implementación de la política de la API

Los siguientes métodos son llamados antes de despachar al método del manejador.

### .check_permissions(self, request)

### .check_throttles(self, request)

### .perform_content_negotiation(self, request, force=False)

## Métodos de despacho

Los siguientes métodos son llamados directamente por el método `.dispatch()` de la vista.
Estos realizan cualquier acción que necesite ocurrir antes o después de llamar a los métodos del manejador como `.get()`, `.post()`, `put()`, `patch()` y `.delete()`.

### .initial(self, request, \*args, \*\*kwargs)

Realiza cualquier acción que necesite ocurrir antes de que se llame al método del manejador.
Este método se usa para hacer cumplir los permisos y la estrangulación, y realizar la negociación de contenido.

Normalmente no necesitarás sobrescribir este método.

### .handle_exception(self, exc)

Cualquier excepción lanzada por el método del manejador será pasada a este método, que devuelve una instancia de `Response`, o relanza la excepción.

La implementación predeterminada maneja cualquier subclase de `rest_framework.exceptions.APIException`, así como las excepciones `Http404` y `PermissionDenied` de Django, y devuelve una respuesta de error apropiada.

Si necesitas personalizar las respuestas de error que tu API devuelve, deberías heredar de este método.

### .initialize_request(self, request, \*args, \*\*kwargs)

Asegura que el objeto de solicitud que se pasa al método del manejador sea una instancia de `Request`, en lugar del `HttpRequest` usual de Django.

Normalmente no necesitarás sobrescribir este método.

### .finalize_response(self, request, response, \*args, \*\*kwargs)

Asegura que cualquier objeto `Response` devuelto por el método del manejador será renderizado en el tipo de contenido correcto, según lo determinado por la negociación de contenido.

Normalmente no necesitarás sobrescribir este método.

# Vistas Basadas en Funciones

> Decir [que las vistas basadas en clases] siempre son la solución superior es un error.
>
> &mdash; [Nick Coghlan][cite2]

REST framework también te permite trabajar con vistas basadas en funciones regulares. Proporciona un conjunto de decoradores simples que envuelven tus vistas basadas en funciones para asegurar que reciban una instancia de `Request` (en lugar del `HttpRequest` usual de Django) y les permite devolver una `Response` (en lugar de un `HttpResponse` de Django), y te permite configurar cómo se procesa la solicitud.

## @api_view()

**Firma:** `@api_view(http_method_names=['GET'])`

El núcleo de esta funcionalidad es el decorador `api_view`, que toma una lista de métodos HTTP que tu vista debería responder. Por ejemplo, así es como escribirías una vista muy simple que simplemente devuelve algunos datos manualmente:

```python
from rest_framework.decorators import api_view
from rest_framework.response import Response

@api_view()
def hello_world(request):
    return Response({"message": "¡Hola, mundo!"})
```

Esta vista usará los renderizadores, analizadores, clases de autenticación, etc. predeterminados especificados en los [ajustes].

Por defecto solo se aceptarán métodos `GET`. Otros métodos responderán con "405 Method Not Allowed". Para alterar este comportamiento, especifica qué métodos permite la vista, así:

```python
@api_view(['GET', 'POST'])
def hello_world(request):
    if request.method == 'POST':
        return Response({"message": "¡Recibí algunos datos!", "data": request.data})
    return Response({"message": "¡Hola, mundo!"})
```

## Decoradores de la política de la API

Para sobrescribir los ajustes predeterminados, REST framework proporciona un conjunto de decoradores adicionales que pueden ser añadidos a tus vistas. Estos deben venir _después_ (abajo) del decorador `@api_view`. Por ejemplo, para crear una vista que usa una [estrangulación][throttling] para asegurar que solo pueda ser llamada una vez por día por un usuario particular, usa el decorador `@throttle_classes`, pasando una lista de clases de estrangulación:

```python
from rest_framework.decorators import api_view, throttle_classes
from rest_framework.throttling import UserRateThrottle

class OncePerDayUserThrottle(UserRateThrottle):
    rate = '1/day'

@api_view(['GET'])
@throttle_classes([OncePerDayUserThrottle])
def view(request):
    return Response({"message": "¡Hola por hoy! Nos vemos mañana!"})
```

Estos decoradores corresponden a los atributos establecidos en las subclases de `APIView`, descritos anteriormente.

Los decoradores disponibles son:

- `@renderer_classes(...)`
- `@parser_classes(...)`
- `@authentication_classes(...)`
- `@throttle_classes(...)`
- `@permission_classes(...)`

Cada uno de estos decoradores toma un solo argumento que debe ser una lista o tupla de clases.

## Decorador de esquema de vista

Para sobrescribir la generación de esquema predeterminada para vistas basadas en funciones puedes usar
el decorador `@schema`. Este debe venir _después_ (abajo) del decorador `@api_view`.
Por ejemplo:

```python
from rest_framework.decorators import api_view, schema
from rest_framework.schemas import AutoSchema

class CustomAutoSchema(AutoSchema):
    def get_link(self, path, method, base_url):
        # sobrescribe la introspección de la vista aquí...

@api_view(['GET'])
@schema(CustomAutoSchema())
def view(request):
    return Response({"message": "¡Hola por hoy! Nos vemos mañana!"})
```

Este decorador toma una sola instancia de `AutoSchema`, una instancia de subclase de `AutoSchema`
o una instancia de `ManualSchema` como se describe en la [documentación de Esquemas][schemas].
Puedes pasar `None` para excluir la vista de la generación de esquema.

```python
@api_view(['GET'])
@schema(None)
def view(request):
    return Response({"message": "¡No aparecerá en el esquema!"})
```
