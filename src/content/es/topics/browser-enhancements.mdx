# Mejoras del navegador

> "Hay dos usos no controvertidos para POST sobrecargado. El primero es _simular_ la interfaz uniforme de HTTP para clientes como navegadores web que no soportan PUT o DELETE"
>
> &mdash; [Servicios Web RESTful][cite], Leonard Richardson & Sam Ruby.

Para permitir que la API navegable funcione, hay un par de mejoras del navegador que REST framework necesita proporcionar.

A partir de la versión 3.3.0 en adelante, estas están habilitadas con javascript, usando la biblioteca [ajax-form][ajax-form].

## PUT, DELETE, etc... basados en navegador

La [biblioteca de formularios AJAX][ajax-form] admite métodos `PUT`, `DELETE` y otros basados en navegador en formularios HTML.

Después de incluir la biblioteca, usa el atributo `data-method` en el formulario, así:

```html
<form action="/" data-method="PUT">
  <input name="foo" />
  ...
</form>
```

Ten en cuenta que antes de la 3.3.0, este soporte era del lado del servidor en lugar de basado en javascript. El estilo de sobrecarga de métodos (como se usa en [Ruby on Rails][rails]) ya no es compatible debido a problemas sutiles que introduce en el análisis de solicitudes.

## Envío de contenido no formulado basado en navegador

El envío basado en navegador de tipos de contenido como JSON es compatible con la [biblioteca de formularios AJAX][ajax-form], usando campos de formulario con atributos `data-override='content-type'` y `data-override='content'`.

Por ejemplo:

```html
<form action="/">
  <input data-override="content-type" value="application/json" type="hidden" />
  <textarea data-override="content">{}</textarea>
  <input type="submit" />
</form>
```

Ten en cuenta que antes de la 3.3.0, este soporte era del lado del servidor en lugar de basado en javascript.

## Sufijos de formato basados en URL

REST framework puede tomar parámetros de URL estilo `?format=json`, que pueden ser un acceso directo útil para determinar qué tipo de contenido debe devolverse desde la vista.

Este comportamiento se controla usando la configuración `URL_FORMAT_OVERRIDE`.

## Sobrescritura de métodos basada en cabeceras HTTP

Antes de la versión 3.3.0, la cabecera de semi extensión `X-HTTP-Method-Override` era compatible para sobrescribir el método de solicitud. Este comportamiento ya no está en el núcleo, pero puede agregarse si es necesario usando middleware.

Por ejemplo:

```python
METHOD_OVERRIDE_HEADER = 'HTTP_X_HTTP_METHOD_OVERRIDE'

class MethodOverrideMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        if request.method == 'POST' and METHOD_OVERRIDE_HEADER in request.META:
            request.method = request.META[METHOD_OVERRIDE_HEADER]
        return self.get_response(request)
```

## Cabeceras de aceptación basadas en URL

Hasta la versión 3.3.0, REST framework incluía soporte incorporado para parámetros de URL estilo `?accept=application/json`, que permitirían sobrescribir la cabecera `Accept`.

Desde la introducción de la API de negociación de contenido, este comportamiento ya no está incluido en el núcleo, pero puede agregarse usando una clase de negociación de contenido personalizada, si es necesario.

Por ejemplo:

```python
class AcceptQueryParamOverride()
    def get_accept_list(self, request):
        header = request.META.get('HTTP_ACCEPT', '*/*')
        header = request.query_params.get('_accept', header)
        return [token.strip() for token in header.split(',')]
```

## ¿HTML5 no soporta formularios PUT y DELETE?

No. En algún momento se pretendía soportar formularios `PUT` y `DELETE`, pero más tarde se [eliminó de la especificación][html5]. Queda [discusión en curso][put_delete] sobre agregar soporte para `PUT` y `DELETE`, así como sobre cómo soportar tipos de contenido distintos de datos codificados en formulario.
