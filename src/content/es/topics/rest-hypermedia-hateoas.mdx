# REST, Hipermedia y HATEOAS

> Sigue usando esa palabra "REST". No creo que signifique lo que tú crees que significa.
>
> &mdash; Mike Amundsen, [conferencia principal de REST fest 2012][cite].

Primero, el descargo de responsabilidad. El nombre "Django REST framework" se decidió a principios de 2011 y se eligió simplemente para asegurar que el proyecto pudiera ser encontrado fácilmente por los desarrolladores. A lo largo de la documentación, intentamos usar la terminología más simple y técnicamente correcta de "APIs Web".

Si te tomas en serio el diseño de una API de Hipermedia, deberías buscar recursos fuera de esta documentación para ayudar a informar tus decisiones de diseño.

Los siguientes entran en la categoría de "lectura obligatoria".

- La tesis doctoral de Roy Fielding - [Estilos arquitectónicos y el diseño de arquitecturas de software basadas en red][dissertation].
- La publicación de blog de Roy Fielding "[Las APIs REST deben estar impulsadas por hipertexto][hypertext-driven]".
- [APIs Web RESTful][restful-web-apis] de Leonard Richardson & Mike Amundsen.
- [Construyendo APIs de Hipermedia con HTML5 y Node][building-hypermedia-apis] de Mike Amundsen.
- [Diseñando APIs de Hipermedia][designing-hypermedia-apis] de Steve Klabnik.
- El [Modelo de Madurez de Richardson][maturitymodel].

Para obtener un contexto más completo, consulta la [lista de lectura de APIs de Hipermedia][readinglist] de Klabnik.

## Construyendo APIs de Hipermedia con REST framework

REST framework es un toolkit de API web agnóstico. Sí ayuda a guiar hacia la construcción de APIs bien conectadas, y facilita el diseño de tipos de medios apropiados, pero no impone estrictamente ningún estilo de diseño particular.

## Lo que proporciona REST framework.

Es evidente por sí mismo que REST framework hace posible construir APIs de Hipermedia. La API navegable que ofrece está construida sobre HTML: el lenguaje de hipermedia de la web.

REST framework también incluye componentes de [serialización] y [parser]/[renderer] que facilitan la construcción de tipos de medios apropiados, [relaciones hipervinculadas][fields] para construir sistemas bien conectados, y excelente soporte para [negociación de contenido][conneg].

## Lo que no proporciona REST framework.

Lo que REST framework no hace es darte formatos de hipermedia legibles por máquina como [HAL][hal], [Collection+JSON][collection], [JSON API][json-api] o [microformatos][microformats] de HTML por defecto, o la capacidad de crear mágicamente APIs completamente estilo HATEOAS que incluyan descripciones de formularios basadas en hipermedia e hipervínculos etiquetados semánticamente. Hacerlo implicaría tomar decisiones opinadas sobre el diseño de APIs que realmente deberían permanecer fuera del alcance del framework.
