# Serializadores anidados escribibles

> Para ahorrar solicitudes HTTP, puede ser conveniente enviar documentos relacionados junto con la solicitud.
>
> &mdash; [Especificación JSON API para Ember Data][cite].

Aunque las estructuras de datos planas sirven para delinear adecuadamente entre las entidades individuales en tu servicio, hay casos en los que puede ser más apropiado o conveniente usar estructuras de datos anidadas.

Las estructuras de datos anidadas son lo suficientemente fáciles de manejar si son de solo lectura: simplemente anida tus clases de serializador y listo. Sin embargo, hay algunas sutilezas más al usar serializadores anidados escribibles, debido a las dependencias entre las diversas instancias de modelo, y la necesidad de guardar o eliminar múltiples instancias en una sola acción.

## Estructuras de datos uno-a-muchos

_Ejemplo de un serializador anidado **de solo lectura**. Nada complejo de qué preocuparse aquí._

```python
class ToDoItemSerializer(serializers.ModelSerializer):
    class Meta:
        model = ToDoItem
        fields = ['text', 'is_completed']

class ToDoListSerializer(serializers.ModelSerializer):
    items = ToDoItemSerializer(many=True, read_only=True)

    class Meta:
        model = ToDoList
        fields = ['title', 'items']
```

Algunos resultados de ejemplo de nuestro serializador.

```json
{
    'title': 'Preparativos de fiesta de despedida',
    'items': [
        {'text': 'Compilar lista de reproducción', 'is_completed': True},
        {'text': 'Enviar invitaciones', 'is_completed': False},
        {'text': 'Limpiar casa', 'is_completed': False}
    ]
}
```
